# ADR-006: 扫码配对网页导入 X 网页会话

Status: Accepted — TV LAN pairing and phone direct Cookie login implemented

Date: 2026-11-16

## 决策

电视采用局域网扫码登录：电视临时启动配对服务并显示二维码，用户用同一局域网的手机浏览器打开电视提供的 HTTP 配对页，手动粘贴自己 X 账号的完整 Cookie 字符串，核对设备与校验码后加密提交；电视通过 X 网页验证真实账号，用户确认后才使用 Keystore 加密保存。不需要公网 HTTPS、中继、付费 API、Android 私有协议或手机伴随 App。

扫码页面不会自动取得其他浏览器的 Cookie，也不冒充 X 官方扫码授权。

手机端按2026-11-17用户要求支持设置内直接填写完整Cookie：与网页使用同等严格解析、只提取必需项，输入默认遮蔽且不保存至界面状态；验证开始、后台或离页清空。身份验证后仍须明确确认账号，才写入相同Keystore。此流程不启动LAN服务，不自动读取浏览器或剪贴板。

## 用户流程

1. TV 创建短时配对会话，展示二维码、设备名称、校验码和有效期。有效期为180秒。
2. 用户扫描后看到配对设备，在唯一的 Cookie 输入框粘贴完整 X Cookie 字符串，例如 `name=value; name2=value2`，也接受带可选 `Cookie:` 前缀的请求头值。页面自动解析并校验 `auth_token`、`ct0`，不提供要求用户分别填写的字段。完整字符串只在手机端临时处理，其他字段不进入传输和存储；不要求导出浏览器整库。

   解析须保留值中的 `=`，去除字段周围空白，接受末尾分号与可选前缀；仅接受单个请求 Cookie 字符串，不把 `Set-Cookie` 属性或整段请求头当 Cookie。拒绝换行注入、畸形键值、缺失/空的必需项与冲突重复的必需项，错误只提示字段名或格式，不回显任何值。
3. 手机与 TV 显示相同校验码，用户明确确认目标设备。提交时以受验证的 TV 公钥加密，会话材料不放 URL、二维码或日志。
4. TV 收到候选会话后进行只读验证，显示真实账号供用户确认。验证失败保留原已登录账号，不提前宣告登录成功。
5. 完成后消费配对会话，清理网页输入与双方临时材料；TV 加密保存账号会话。可本地移除会话；本地注销不代表已经在 X 服务端撤销。

配对页允许粘贴，字段默认遮蔽，显式操作才显示。错误提示不得回显凭据。UA 等协议诊断信息应尽可能由客户端维护；不作为普通用户必填项，也不能声称手机配对页 UA 就是原登录浏览器 UA。

## 传输与安全约束

电视绑定单个私有IPv4局域网地址及随机端口，只提供APK内置的允许列表静态资源与密文提交路径。配对180秒有效，离开登录页或切后台关闭服务。提交检查精确Host、同源Origin、长度、算法、ID和有效期，单次消费；错误来源或畸形密文不能修改已有账号。

手机HTTP页面使用内置node-forge与浏览器CSPRNG；HTTPS/回环开发环境可使用Web Crypto。RSA-OAEP SHA256（显式MGF1 SHA256和label）包装AES256GCM密钥，上下文绑定版本、ID、有效期、设备名与TV公钥，双方显示同一校验码。**应用层密文不认证通过HTTP下载的页面脚本；局域网主动攻击者若篡改页面，校验码不能保护被替换脚本中的输入。此方式依赖可信局域网与可信浏览器，不等价于HTTPS的页面完整性保证。** 不承诺内存取证级清零。

- 固定局域网方式，无公网部署；无需开放路由器端口。网络隔离或手机浏览器局域网权限拒绝时，需由用户处理后重新配对。

- 使用成熟密码库和协议，绑定配对ID、协议版本、TV临时公钥及有效期，并利用双方校验码核对目标设备与密钥；不能仅凭短码领取会话。
- 一次性随机配对标识，不可枚举；短有效期、有限请求预算和大小限制；过期、取消、重复提交、重放、抢先绑定都应拒绝或明确处理。
- 局域网提交接口只接收密文，不记录请求正文；页面不加载第三方统计、广告或非必要脚本，使用APK内固定资源和CSP。
- Cookie 不进入 query、path、fragment、剪贴板自动操作、应用日志、崩溃报告、分析事件或 Git；网页不持久保存输入，TV排除凭据备份。
- 会话按账号隔离，使用适合系统版本的加密存储。最低API23，需验证不同设备的Keystore可用性；安全存储不可用时明确报告，不保存明文。
- 协议只向精确允许的 X API 域发送账号凭据，不跟随跨域重定向泄露 Cookie；公开数据服务与任意媒体CDN不可收到账号授权头。

## X 网页协议实现边界

当前通过 `https://x.com/home` 的 `window.__INITIAL_STATE__` 确认 `session.user_id`，并与 `entities.users.entities[id].id_str`、screen_name交叉匹配。共享OkHttp客户端精确固定X网页源，拒绝重定向；不依赖捕获的Bearer、单次transaction或Android协议。完整输入仅在手机临时解析，只有auth_token/ct0进入密文，其他Cookie丢弃。账号摘要显示供TV确认，再保存到API23+ Keystore AES-GCM密文；最低安装版本为API23。

媒体Provider需持续维护当前网页GraphQL操作配置、CSRF、事务标识、响应与分页；身份验证与媒体调用分别验收，当前结果见验证记录。不得将账号凭据发往公开数据Provider或媒体CDN。

显式区分会话失效、挑战、访问受限、限流、网络故障、协议变化；检查HTTP200中的GraphQL错误。401/403/429/挑战时停止对应调用并引导人工处理，不伪造设备证明、验证码或指纹，不切账号/代理继续消耗额度。未验证的能力不宣告支持，也不静默切换Guest/Demo。

决策已采纳并完成局域网扫码与身份登录。真实API28电视已验收二维码解码→手机局域网HTTP页面填Cookie→密文提交→TV网页身份验证→确认→加密保存、冷启动恢复、重新验证与退出清理；Host/资源/Origin/畸形密文拒绝与后台关闭端口也已实测。完整过期/重放并发/账号切换/错误Cookie/其他API矩阵尚未全部执行。真实关注媒体流、分页与播放已在后续本机迭代实现；用户主页媒体仍待完成。[协议与测试](../../web/pairing/README.md)及[证据](../development/verification.md)记录实际边界。Passkey、官方OAuth或手机伴随端不作为首版必需登录链路。
